AWS infers, Azure declares — and Kubernetes never notices

Every resource both providers create, keyed to the part of Kubernetes it exists for. Kubernetes only ever sees four things: machines that reach each other, an apiserver port, an identity on the metadata service, and an object store for backups. Everything on this page is scaffolding for one of those four — and the proof is that cluster/ has survived three provider swaps unchanged.

1The machines — where kubelet lives

2Node addressing — what the certs and peers depend on

FOR KUBERNETES: apiserver cert SANs · etcd peer list · every kubeconfig

The private IPs are the load-bearing ones. 10.0.1.10/11/12 appear in the apiserver certificate, the etcd peer configuration, and every kubeconfig — which is why both providers pin them statically and the address plan has never changed across three clouds. The public IPs exist only for the admin path (SSH, kubectl from the laptop, the Cloudflare A record); the cluster itself never dials them.

3The network fabric — etcd peers, kubelet API, the CNI overlay

FOR KUBERNETES: etcd 2379/2380 · kubelet 10250 · apiserver↔kubelet · Cilium VXLAN

The placement asymmetry is a scar, not a style choice: Azure's identity lives in the persistent group because a CanNotDelete lock blocks deleting role assignments scoped inside it — an ephemeral stack owning the grant could never be destroyed (409 ScopeLocked, ADR 009 addendum 2). Rule extracted: identity that grants access to durable data lives with the data.

6The durable half — what make destroy must not touch

FOR KUBERNETES: CNPG's barmanObjectStore — WAL archiving + base backups, the data that outlives the cluster

Drill 3 proved etcd snapshots don't cover PV data; phase 7.1 proved a destroy takes the database with it. Both clouds solve it with a lifecycle boundary — but they enforce it differently, and that difference is the deepest one on this page.

The shape of the difference: AWS infers — one instance resource implies its NIC and public IP, rules imply direction and ordering, but internet egress needs explicit gateway-and-route plumbing. Azure declares — NIC, public IP, rule priorities, and identity are first-class objects you wire together, but routing, egress, and intra-VNet traffic come free. Kubernetes never notices either way, because the only surface it touches is the nodes contract — the same five fields, three swaps in a row.
