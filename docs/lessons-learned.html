The lessons above the lessons

Five patterns that kept recurring across every phase.

Drills find bugs that reading never will

Drill 1 found the SSH-readiness race. Drill 2 found the naked-session mistake. Drill 4 proved nodes were cattle. Later, the Postgres card found an unpinned secret, a lying resource request, and an entire era running with no backups. Every deliberate breakage returned a real fix — none would have surfaced from documentation.

The dangerous failures are the quiet ones

archived_count climbing against an empty bucket. "Expected empty archive" leaving a whole generation backup-less while every app stayed green. A Cluster with no status at all under a fully Synced GitOps board. None raised an alarm; all three were caught only by inspecting the artifact itself — listing the bucket, reading the instance log, asking whether the resource actually has a status.

The instrument fails more than the system

The final drill took three attempts and every failure was in the measuring harness, not the cluster: it timed an idempotent no-op and reported confident numbers, died before printing its own scorecard, then blocked on stdin that backgrounding had removed. Across the whole card, the serious outages traced to configuration and tooling — rarely to Kubernetes or Postgres.

Idempotency is the feature that pays for everything

Every recovery story ends the same way: re-run the same command. The interrupted upgrade, the double bootstrap, the node replacement — all healed because scripts skip what's done and redo nothing they shouldn't.

Everything of value lives in three places

Git (manifests, scripts), Pulumi state (infra), two local secret files. The cluster itself held nothing worth keeping — the design goal that made an 8-minute rebuild possible. Phase 7's Postgres is the first thing to change that.

Control plane down ≠ outage

Seen three times, most starkly in drill 3: etcd and the API server stopped, kubectl refused — and the hello app served HTTP 200 throughout. Running pods, routing, and Cilium don't need the API; you just can't change anything.

Observability installed early pays off later

Hubble went in with Cilium in Phase 3 as a nice-to-have. In Phase 4 it ended a four-step debugging mystery in one command. Logs say "timeout"; the network observer says why and where.

Build it by hand to make the tool legible

"Failover in 2 seconds" is a number. "2 seconds instead of the three minutes we spent typing RECONNECT into two pgbouncer pods" is a lesson. An operator's value isn't that it works — it's which problems it makes structurally impossible, and that list is only visible from the far side of having had them.

An abstraction is a hypothesis until something tests it

The provider-agnostic seam was designed on day one and believed for three weeks. Losing the AWS account forced the experiment: cluster/ unchanged, bootstrap.sh working on Azure first try. What earned it wasn't cleverness — it was carrying sshUser as data, pinning the address plan, and refusing to install a cloud-controller-manager. Discipline you can't evaluate until the day you need it.

Cloud providers & IaC

What AWS, Hetzner, and Pulumi taught us about the layer beneath the cluster.

Re-verify pricing folklore — it has an expiry date.
Hetzner's June 2026 repricing flipped the usual advice: ARM (CAX11 €5.99) became more expensive than budget x86 (CX23 €5.49). "ARM is the cheap option" was true until it wasn't.
jul 13 · ADR 001observed
A provider listing a product ≠ having capacity.
Hetzner had no CX23 VMs when it was time to provision. The forced AWS pivot produced the project's best idea: the provider-agnostic inventory contract, with on-prem as an explicit target.
jul 13 · ADR 002bitten
Firewall semantics differ per cloud — and the seam must absorb it.
Hetzner firewalls filter only the public interface; AWS security groups filter all traffic, so node-to-node needs an explicit self-referencing rule. Exactly the class of difference the inventory contract exists to contain.
jul 13observed
Even the SSH login user is provider-specific.
Hetzner Ubuntu logs in as root, the AWS Ubuntu AMI as ubuntu. Encoded as sshUser in the contract instead of assumed anywhere.
jul 13observed
Pulumi handles partial failure by remembering the successes.
First pulumi up: 10 of 11 resources created, then AWS's new-account PendingVerification blocked the third instance. State recorded the 10; the retry created only the missing one. Second run: clean.
jul 13observed
Cloud addons pull cloud identity in with them.
One storage driver (EBS CSI) brought an IAM role, an instance profile, a iam:PassRole requirement on every future pulumi up, and a permanent switch to the admin profile. Nothing cloud-flavored is ever just a Helm chart.
jul 14 · phase 4bitten
IMDS hop limit 2 is one too few with an overlay CNI.
TCP handshakes survived but every response data packet died — Hubble showed TTL exceeded DROPPED on each one. One hop into the node stack, one crossing Cilium into the pod veth. Fix: hop limit 3, set in Pulumi.
jul 14 · phase 4bitten
The browser SSO session belongs to whoever logged in last.
An aws sso login for the poweruser profile, approved by a browser session holding the admin user, mints a token that 403s when asking for the PowerUser role. Identity Center users also sign in at the access-portal URL, not the normal AWS page.
jul 13–14bitten
A state-lock error doesn't mean an operation is running.
The S3 backend held a lock from a pulumi destroy whose process had died. Check the pid in the lock message; if it's gone, pulumi cancel is safe.
jul 18 · resurrectionbitten
Admin IP drift is a guaranteed recurring failure — check it mechanically.
The security group faithfully enforced a stale myIp after the ISP rotated, locking us out at the TCP level. Fixed at the right layer (pulumi config set myIp), then automated: make check-ip runs before every up. It caught the next drift mid-session three days later.
jul 18 · resurrection + 7.1bitten
AWS costs ~7× Hetzner for the same shape — teardown habits close the gap.
t3a.medium at ~$27/mo vs CX23 at €5.49/mo. Hourly billing, ~$200 of new-account credits, and pulumi destroy between sessions make each 3-hour lab cost about $0.35.

Kubernetes internals

What kubeadm, upgrades, and node drills exposed about how the machine actually works.

The control plane hosts itself via static pods.
etcd, the API server, scheduler, and controller-manager are YAML files in /etc/kubernetes/manifests/, run by the kubelet straight from disk — no scheduler involved. "Stopping etcd" in drill 3 was mv-ing a file out of that directory.
jul 14 + drill 3observed
NotReady × 3 can be a success state.
A kubeadm cluster without a CNI is supposed to be NotReady. Control-plane pods run anyway (hostNetwork); CoreDNS stays Pending because it needs a pod network — the visible difference between the two. It waited 24 minutes for a network to exist, then scheduled.
jul 14 · phase 2–3observed
Version-skew tolerance is what makes rolling upgrades possible.
A mixed cluster (control plane on 1.36, workers on 1.35) is a supported, normal mid-upgrade state — not an accident to rush out of. The hello app returned 200 at every checkpoint, including during the etcd swap.
jul 15 · drill 2drilled
kubeadm upgrade apply is designed to be interrupted.
When SSH died mid-upgrade and took kubeadm with it, the kubelet had already finished the etcd swap from the new manifest; re-running the apply completed idempotently. It's resumable on purpose.
jul 15 · drill 2bitten
Node name is captured at registration and is immutable after.
A worker about to join with hostname ip-10-0-1-11 would have kept that name forever. Set the hostname before kubeadm join — caught just in time.
jul 14 · phase 2bitten
There is no "node replacement procedure" — that's the achievement.
An unannounced AWS-level termination was healed by the same two idempotent commands as everything else: pulumi up + make bootstrap. Replacement Ready in ~7 minutes, same private IP (fixed addressing pays off). Nodes are fully cattle.
jul 15 · drill 4drilled
Kubernetes hedges 5 minutes before evicting pods from a dead node.
NotReady arrived in under a minute (kubelet heartbeat), but pod eviction waits a further 5 minutes by default — a tolerance against network blips, auto-added to every pod. For a known corpse, kubectl delete node short-circuits it (and is required anyway before a same-name rejoin).
jul 15 · drill 4drilled
Drain evicts pods but not DaemonSets — by design.
Cilium and CSI pods stay put during a drain (hence --ignore-daemonsets); they're per-node infrastructure, not workloads to migrate.
jul 15 · drill 2observed
After maintenance, workloads sit wherever history put them.
Both hello replicas ended up on worker-1 — evicted there during the upgrade drill and never rebalanced. The scheduler places on creation; it doesn't rebalance. kubectl rollout restart or a descheduler if it matters.
jul 15 · drill 4observed
Not every error is real — some are just "too early".
A transient Forbidden right after the kubelet restart was the API server still warming up (RBAC not yet synced). The retry succeeded. Distinguish broken from booting.
jul 15 · drill 2observed

Networking & the edge

Cilium, the kube-proxy retirement, and the Gateway API migration.

The CNI's default pod CIDR can contain your VPC.
Cilium's default pool is 10.0.0.0/8 — which includes the 10.0.0.0/16 VPC; pods would have collided with machines. The one critical Helm value: pin the pool to kubeadm's --pod-network-cidr (10.244.0.0/16).
jul 14 · phase 3decided
Logs say "timeout"; Hubble says why and where.
Four debugging steps (driver logs, pod-side probes, instance metadata options, NAT rules) narrowed nothing. One command — hubble observe --ip 169.254.169.254 — showed every response packet dropped with TTL exceeded. The Phase 3 observability install solved the Phase 4 mystery.
jul 14 · phase 4bitten
Replacing kube-proxy has a chicken-and-egg hiding in it.
Cilium agents normally reach the API through the in-cluster kubernetes Service VIP — but translating that VIP was kube-proxy's job. The real API server address must be passed explicitly (k8sServiceHost), and it comes from the inventory, not values.yaml.
jul 18 · phase 6.5observed
Order matters when swapping the service plane live.
Enable Cilium's replacement first (eBPF and iptables coexist), verify KubeProxyReplacement: True, and only then delete the DaemonSet and flush KUBE-* rules. Delete-first would have left services untranslated.
jul 18 · phase 6.5drilled
CRDs must exist when the controller starts, or it never registers.
Cilium only registers its Gateway API controller if the CRDs are present at agent start. The install order (CRDs → helm) is now encoded in bootstrap.sh so rebuilds can't get it wrong.
jul 18 · phase 6.5observed
hostNetwork Envoy is the portable answer to "no cloud load balancer".
The Gateway binds listener ports directly on every node — the Gateway-API-era version of ADR 003's NodePort stance. Keeping nginx's exact ports (30080/30443) meant the SG rules, DNS record, and every URL survived the cutover unchanged.
jul 18 · ADR 005decided
A hostNetwork Gateway reports PROGRAMMED=False forever. It's fine.
There's no LB Service to copy an address from, so the status never turns true. Verify with curl, not status — noted in the runbook so future-us doesn't "fix" a working gateway.
jul 18 · phase 6.5observed
DNS-01 means real certificates with zero inbound ports.
Ownership is proven with DNS records on Cloudflare; Let's Encrypt never contacts the cluster. Port 80 was never opened, and re-issuance after a rebuild worked even while the A record still pointed at the dead IP.
jul 14 · phase 5observed
Gateway API's role split is real: apps route, infra terminates.
The app's HTTPRoute has no TLS config at all — hostname and backend, nothing else. The wildcard cert and ports live on the Gateway. One wildcard cert means a new app is just HTTPRoute + DNS; Phase 7's capstone gets HTTPS for free.
jul 18 · phase 6.5observed

GitOps, secrets & operations

The operating model, and what it takes to keep credentials boring.

Once ArgoCD owns an app, kubectl apply becomes drift.
Git holds the desired state; the cluster converges to it, and selfHeal reverts manual edits. The app is no longer deployed by anyone. This is the operating model everything after Phase 5 builds on.
jul 14 · phase 5observed
The GitOps dividend: after a rebuild, apps restore themselves.
Drill 1's fresh cluster: ArgoCD came up, read its repo credential, found the Application, pulled main, deployed — Synced/Healthy with zero human involvement. The only manual steps were DNS and noting a new admin password.
jul 15 · drill 1drilled
"Synced/Healthy" can be a stale revision.
ArgoCD polls every ~3 minutes, so a fresh push may not be reflected yet. Force a refresh (the argocd.argoproj.io/refresh annotation) before concluding a push didn't work.
jul 18 · phase 6.5observed
GitHub deploy keys are one-repo-per-key — and the error lies.
"Key is already in use" actually meant the first add had succeeded. A dedicated read-only deploy key per repo is the pattern; don't reuse.
jul 14 · phase 5bitten
Secrets go terminal-only, and "roll" is the cheap response to exposure.
The Cloudflare API token got pasted into an AI-chat transcript → rolled immediately. Rekeying costs minutes; wondering whether an exposure mattered costs more.
jul 14 · phase 5bitten
Scope API tokens by blast radius, not convenience.
Cloudflare tokens scope to whole zones — a leaked in-cluster token means DNS control of everything in that zone. Hence a dedicated low-stakes domain (kahng.dev) instead of the daily-driver zone.
jul 14 · phase 5decided
Ownership references garbage-collect more than you deleted.
Removing the Ingress from git let ArgoCD prune the live object — and its ingress-shim Certificate followed automatically via ownerRef GC. One orphaned Secret still needed a manual sweep; know which resources own which.
jul 18 · phase 6.5observed
DNS lives outside the cluster — and it's the last manual step.
After every rebuild, the wildcard A record must be pointed at the new control-plane IP by hand. Everything else self-restores. Flagged as the next automation candidate (external-dns or a small script on the existing token).
jul 15–18observed
The Applications themselves aren't GitOps-managed.
A fix committed and pushed to cluster/gitops/*.yaml changed nothing — platform.sh applies those files imperatively once, and nothing watches them after. Twenty minutes of "why isn't my fix working" before a hand kubectl apply — the exact indignity GitOps exists to remove. App-of-apps graduated from loose end to prerequisite, with a dated incident attached.
jul 29 · 7.4bitten
selfHeal reverts drift; it does not retry defeats.
Automated sync had exhausted its attempts on that revision, and changing the syncPolicy doesn't count as a new one — so nothing would ever retry on its own. A sync must be requested explicitly. Three reasonable ArgoCD behaviours composing into "nothing is happening".
jul 29 · 7.4bitten
Megabyte CRDs need server-side apply.
Client-side apply stuffs the whole object into the last-applied-configuration annotation, which caps at 256KiB. CNPG's two biggest CRDs silently failed while nine others landed — so the operator crash-looped on no matches for kind "Cluster", a symptom four layers from its cause. ServerSideApply=true tracks field ownership in the apiserver instead.
jul 29 · 7.4bitten
selfHeal fights you during surgery — pause it deliberately.
Wiping PVCs and DCS state raced ArgoCD recreating the StatefulSet, which re-pinned the Terminating volumes. Set syncPolicy.automated: null, do the work in order, then restore the policy from git. The dividend and the obstacle are the same feature.

State & storage

From "a fresh cluster has no StorageClass" to running Postgres on purpose.

A fresh kubeadm cluster has no StorageClass at all.
A PVC just Pends — the storage version of CoreDNS-without-CNI. Nothing provisions volumes until you install something that does.
jul 14 · phase 4observed
WaitForFirstConsumer keeps PVCs Pending on purpose.
The volume can't be placed until a pod schedules, so binding waits for the consumer — Pending is the design, not a failure.
jul 14 · phase 4observed
Local storage pins the workload to the data's node.
Cordoning postgres-0's node left it Pending while a free node sat idle — the data wasn't there. The scheduler message reads like a tour: PV affinity, taints, unschedulable. Network storage (ebs-sc) follows the pod instead; that contrast is the whole local-vs-network decision in one drill.
jul 14 + jul 18 · 7.1drilled
etcd snapshots capture Kubernetes objects, not volume contents.
A restore with missing volumes is pods pointing at ghosts. Postgres data needs its own backup story (volume snapshots, pg_dump, WAL archiving) — and the drill's snapshot living on the node it protects is fine for a drill, useless for a real node loss.
jul 15 · drill 3drilled
An etcd restore is time travel for the whole cluster.
Proven with markers: a configmap created before the snapshot survived; one created after was erased. On a shared cluster, restoring to fix one thing reverts everyone else's changes too.
jul 15 · drill 3drilled
StatefulSet guarantees are three separate, observable things.
Stable identity (the replacement pod is already named postgres-0), storage that follows the ordinal (the survival row was still there), and per-pod DNS via the headless Service. Each was drilled individually — the primitives Patroni's primary/replica split builds on.
jul 18 · 7.1drilled
Stateless and stateful, side by side, is the fastest way to see the difference.
pgbouncer (Deployment): random names, no PVC, reschedules anywhere, replicas cost nothing. postgres-0 (StatefulSet): none of those freedoms. Same phase, both kinds, deliberately contrasted — along with VIP Service (don't care who answers) vs headless (care exactly who answers).
jul 18 · 7.2decided
Connection pooling is multiplexing, not magic — and it has a price.
Five clients, a pool of two, zero failures: server connections are borrowed per transaction and returned at commit. The trade: session state (SET, LISTEN, advisory locks) dies at transaction end; prepared statements need max_prepared_statements.
jul 18 · 7.2drilled
Pool math multiplies by replica count.
Two pgbouncer pods × pool of 2 = up to 4 real backends, and per-pod admin consoles mean no fleet view. Sizing rule: real ceiling = pool_size × pooler replicas. (Fleet-wide visibility is what operators and metrics exporters add.)
jul 18 · 7.2bitten
Secrets can transit to config without touching git or disk.
pgbouncer's auth_file — which must hold the plaintext password for SCRAM on both legs — is rendered by an init container into a memory-backed tmpfs from the same Secret postgres uses. Nothing new in git, nothing on disk.
jul 18 · 7.2decided
postgres:18 reorganized its volume layout for in-place major upgrades.
Mount /var/lib/postgresql (not .../data); PGDATA lives in a version directory underneath so a future pg_upgrade --link can run inside one volume. Worth knowing before any 7.x touches upgrades.
jul 18 · 7.1observed
Backups can fail at the granularity of an entire generation, silently.
CNPG refuses to archive a new cluster into a prefix holding a dead cluster's WALs ("Expected empty archive") — and the refusal surfaces only as ContinuousArchiving: False while every app stays green. A rebuild had been running with no working backups at all and nothing said so. Every rebuild now bumps a dated serverName.
aug 25 · runbook 06bitten
"Waiting" and "deadlocked" look identical from a status field.
A replica sat on Waiting for the instances to become active for 40 minutes. The instance log had the truth: pg_rewind needed the WAL segment that was open when its node died — never archived, gone. The operator retried the impossible forever rather than escalating. Deleting the PVC and letting it re-clone took 32 seconds.
aug 18 · runbook 07bitten
Read the CRD, not the docs, when they disagree.
The upstream migration guide showed retentionPolicy as an object; the installed CRD declared it a string and rejected the object outright. One kubectl get crd -o jsonpath settled in a second what the docs got wrong.
aug 28 · barman pluginbitten
Migrate backup machinery while the cluster is dead, not while it is live.
Moving off in-tree barmanObjectStore (deleted in CNPG 1.31) was done as a birth rather than a migration, because the cluster had already been destroyed. Three schema surprises and a silent reconcile race followed — each of which would otherwise have hit a working database mid-rollout. The archive format is unchanged, so the plugin reads what the old code wrote; only the configuration pointing at it moved.

Changing clouds — what the migration taught

AWS account access was lost on 2026-08-05, taking the Pulumi state backend and every Postgres backup with it. The forced rebuild on Azure became the only real test the provider-agnostic design ever got.

The abstraction held — and the thing we didn't build is why.
Changed: the Makefile header and a new infra/azure/. Unchanged: prep-node, bootstrap, every Cilium and gateway value, all of apps/ and gitops/. make bootstrap brought up v1.36.3 on Azure first try. Three earlier calls earned it — the contract carrying sshUser as data, an identically pinned address plan, and ADR 003's refusal to install a cloud-controller-manager. Three weeks of resisting the convenient option paid off in one afternoon, because there was no cloud integration to port.
aug 5 · ADR 009drilled
Every cloud answers the firewall question differently.
Hetzner filtered only the public interface, leaving private traffic open. AWS denied everything including node-to-node, forcing an explicit self-referencing rule. Azure permits all intra-VNet traffic by default (built-in AllowVnetInBound), so that rule has no counterpart — etcd, kubelet and VXLAN work with nothing declared. Three clouds, three answers, and the seam absorbed all of it.
jul 13 → aug 5observed
A provider listing a product ≠ having capacity for you. Now 4-for-4.
Hetzner had no CX23s. AWS held a new account's third instance for PendingVerification. Azure capacity-restricts the entire B-series on trial subscriptions, then caps Total Regional vCPUs at 4 — identical in every region checked, so relocating doesn't help. Four occurrences of one lesson across three clouds.
aug 5 · ADR 009bitten
The tool that lists sizes is not the tool that knows what you can have.
az vm list-sizes cheerfully reports Standard_B2als_v2 as available in eastus. Creating it fails 409 SkuNotAvailable. Only az vm list-skus's restrictions field tells the truth: of 522 SKUs visible, just 16 two-vCPU sizes are usable. Availability and entitlement are different questions, and only one API answers the second.
aug 5 · ADR 009bitten
Quota shapes architecture: per-role VM sizing.
Three 2-core nodes need 6 vCPUs; the cap is 4. The fix keeps the whole topology inside it — a 2-core control plane (kubeadm's NumCPU preflight requires 2) plus two 1-core workers, every node still 4 GiB. AWS used three identical machines; heterogeneous sizing is arguably closer to real practice anyway. Sequencing trap: at exactly 4/4 cores, shrinking one node and creating another in a single pulumi up deadlocks — targeted-destroy first.
aug 5 · ADR 009decided
Hand-made bootstrap knowledge dies with the account.
The AWS Pulumi state bucket was created by hand and documented only in a journal sentence. When access vanished, so did every trace of how it had been set up. The Azure equivalent is infra/azure/foundation.sh — a script that creates the locked resource group, versioned state storage, Key Vault, service principal and SSH key, idempotently. The chicken-and-egg layer deserves code precisely because Pulumi can't manage it.
aug 5 · ADR 009bitten
Put the secrets provider in the cloud, not on the laptop.
The AWS setup warned in its own notes that losing ~/.config/pulumi/trk-k8s.passphrase would make stack secrets unrecoverable. Azure Key Vault replaces it. The encryptedkey in the stack file is safe to commit — it's the data key encrypted by the vault key, useless without vault access.
aug 5 · ADR 009decided
A fresh Azure subscription has almost nothing registered.
Resource providers (Storage, KeyVault, Compute, Network, ManagedIdentity) are NotRegistered by default, and creating an unregistered type fails with an error that reads like a permissions problem. Registration is async, per-subscription and permanent — do it once, up front, and wait for it.
aug 5bitten
Azure's spending limit is better protection than AWS ever offered.
On a free trial it's ON by default and disables resources rather than charging the card when credits run out. Azure repeatedly invites you to remove it; don't. Budgets, by contrast, only notify — the same lesson the AWS "$1 zero-spend budget" taught, relearned. And credits expire 30 days from signup regardless of use, so the clock binds before the money does.
aug 5observed
Least privilege only teaches you something when it actually bites.
On AWS, PowerUserAccess genuinely couldn't call iam:* — which forced a second admin identity and taught the iam:PassRole lesson. On a personal Azure tenant, splitting owner from admin gives two identities with identical powers, because Conditional Access and PIM need Entra ID P2. The separation worth having is human-vs-automation: Pulumi runs as a service principal, never as you. Skip the ceremony that has no mechanism behind it.
aug 5decided
Contributor cannot grant roles.
The Pulumi service principal needs Role Based Access Control Administrator alongside Contributor, because the node's managed identity requires a role assignment and Contributor can't create one. Both together are still narrower than Owner.
aug 5bitten
Hardening has a floor: the tool has to still work.
Shared-key access stays enabled on the state storage account because Pulumi's azblob backend authenticates with an account key; disabling it would harden the backend into uselessness. Everything else got locked down — no public blob access, TLS 1.2 floor, HTTPS only, versioning plus 30-day soft delete, since state corruption is recoverable and state deletion is not.
aug 5decided
Azure models the lifecycle boundary natively.
ADR 008 needed a second Pulumi stack and a StackReference to stop backups dying with the cluster. Azure expresses the same idea as two resource groups, one carrying a CanNotDelete lock the platform itself enforces — stronger than ForceDestroy: false, and an object rather than a convention.
aug 5 · ADR 008/009observed
A typed SDK turns deploy-time failures into compile errors.
Three enum names were not what they looked like — IPAllocationMethodStatic not Ip…, DiskStorageAccountTypes_StandardSSD_LRS not StorageAccountTypes…. The compiler caught all three before a single API call. Worth remembering next time the Pulumi-vs-YAML question comes up.

ArgoCD's controller reported no route to host to its repo-server — exactly what a broken overlay on a new cloud would look like. It was the repo-server still starting. cilium-dbg node list showing all three nodes with correct CIDRs is what ruled out a real problem. aug 5 · ADR 009observed

Postgres HA — hand-built, then operated

Phase 7.3 built Patroni by hand; 7.4 replaced it with CloudNativePG and re-ran the identical drills. Almost everything here was found by breaking something on purpose.

Fencing comes from the leadership model, not from the DCS.
We recorded in ADR 006 that using the Kubernetes API for consensus buys "control-plane outage = write outage" — Patroni self-fenced within its 30s lease and proved it. Then CNPG, on the same API, rode out a 7-minute apiserver outage without dropping a write. Patroni's leader holds a renewable lease and any member may self-promote, so a leader who can't renew must demote. CNPG centralizes promotion in the operator: if the API is gone nobody can promote, so the incumbent is safe to continue. Corrected in ADR 007.
jul 28 + jul 31drilled
It knew, and chose — check before assuming ignorance.
CNPG's primary logged 128 Failed to watch errors during the outage. The difference between "survived because it's well designed" and "survived because it never noticed" is worth one log query, and it's the whole difference between a finding and a coincidence.
jul 31 · 7.4observed
Failover isn't finished until the pooler lets go.
Our hand-built database completed its failover at 08:26; the application couldn't write until 08:29. pgbouncer's pooled connections stayed pinned to the demoted primary — established TCP doesn't follow Endpoints. Worse, firing RECONNECT through the Service VIP hits one pod at random, visible as OK/ERROR flapping; it took per-pod-IP commands to flush both. CNPG's Pooler closes this in 2s because one controller owns promotion and the pool.
jul 28 · 7.3bitten
Passive lease expiry vs active health probes: 30s vs 2s.
Patroni infers death from absence — silence for a full TTL. CNPG health-checks every instance, so a failed readiness probe is direct evidence. Same job, opposite epistemology, and most of the detection-time gap.
jul 31 · 7.4observed
Two recovery layers that don't know about each other race by accident.
Killing the primary on a healthy node caused no Patroni failover: the StatefulSet controller resurrected the pod faster than the 30s TTL could expire. Neither system decided anything — the faster one won. CNPG owns both pod lifecycle and failover, so it chose: promote the replica, rebuild the dead one as a replica.
jul 28 + jul 31drilled
A cordon is a no-op to one system and a drain signal to another.
Cordoning was our technique for blocking pod resurrection — inert to Patroni. CNPG watches for the unschedulable taint and gracefully evacuates the primary before you disturb anything. Node maintenance is safe by default; it also invalidated our drill recipe by being too careful.
jul 31 · 7.4observed
The leader Service must be named exactly the scope.
In use_endpoints mode Patroni strips -leader, so its lease lives on Endpoints/<scope>. Our headless Service already owned that name — so the endpoints controller and Patroni fought over one object, Patroni lost every compare-and-swap, and the only symptom was Could not take out TTL lock with no error. A successful initdb followed by an immediate self-demotion, forever.
jul 26 · 7.3bitten
Patroni appends a label to its member selector that it never stamps.
The pod selector is kubernetes.labels plus cluster-name=<scope>, added automatically — but only the role label gets written to pods. Without it the member watch matches zero pods: elections still work, but a replica can't resolve the leader's connection URL and fails in ~1ms with a bare "failed to bootstrap from leader", wiping its data dir on every retry.
jul 26 · 7.3bitten
A database with its own coordinator must not inherit the StatefulSet's.
OrderedReady deadlocks when the initialized data sits on a higher ordinal: ordinal 0 waits for a leader to clone from while the leader-to-be waits for ordinal 0 to be Ready. podManagementPolicy: Parallel — Patroni's DCS race is the only ordering needed. CNPG went further and abandoned StatefulSets entirely.
jul 26 · 7.3bitten
One trailing newline can split env auth from file auth.
openssl rand … > file ends with \n. The env var carried it, so Patroni created the role with password\n — but pgpass is line-oriented and dropped it, so pg_basebackup sent password. The database held one value and the wire carried another, both "the secret". Diagnosed by comparing byte counts, never printing the value.
jul 26 · 7.3bitten
Rewind and data loss have the same precondition.
A deposed leader needs pg_rewind only if it holds commits the new leader never saw — which is exactly when async replication would have lost data. Ours needed no rewind: its last LSN sat at the fork point, so recovery just fetched the new timeline's history and fast-forwarded. Two sides of one coin, observed on both faces.
jul 28 · 7.3drilled
archived_count climbing is not evidence of backups.
It reached 15, and the cluster condition read "Continuous archiving is working", while the S3 bucket was empty — CNPG's archive command exits 0 when no destination is configured. A green dashboard and no backups. The only honest check is listing the bucket. After the fix, failed_count climbed instead: failing loudly beats succeeding falsely.
jul 31 · 7.4bitten
Image variants can differ by capability, not just size.
We picked CNPG's standard image to mirror our hand-built postgres:18 — the one variant that dropped the barman-cloud binaries, because backups are migrating to a plugin. The operator's own default (system) was the answer all along; we overrode it for symmetry and paid in a debugging session.
jul 31 · 7.4bitten
RPO measured, not assumed: the currently-open WAL segment.
Restored a base backup plus archived WAL into a cluster that didn't exist when the backup was taken — 52 seconds, and exactly one row of 660 missing: the marker written after the last archived segment. Specific and explainable, which is what you want before an incident rather than during one.
jul 31 · 7.4drilled
Timelines are the forensic record of promotions.
Postgres increments the timeline on every promotion, so the number is a tamper-proof count of how many times leadership changed. Our "non-event" drill — where no failover happened — still left a timeline bump as its only trace.
jul 28 · 7.3observed
Bootstrap belongs in its own disposable pod.
CNPG runs initdb and restores in dedicated job pods (pg-1-initdb-*, pg-restored-1-full-recovery-*) — observable, separate, thrown away. Our Patroni stack bootstrapped inside the container that would later serve queries, so the same logs carried both. The operator's instinct showed up three separate times.

Operator craft

Terminal discipline — the small mistakes that cost the most time.

Long remote operations run under nohup or tmux, never naked in a session.
SSH died at the etcd swap (peak memory on a 4GB node) and took the upgrade process with it — it was a child of the session. Recovery worked because kubeadm is idempotent; the habit is the fix.
jul 15 · drill 2bitten
Join commands go on one line, always.
A multi-line paste wrapped the CA hash; the shell ran the tail of the hash as its own command and the join used a truncated hash. (Related: never paste live join tokens into git-tracked docs.)
jul 14 · phase 2bitten
Don't pipe long-running commands through tail.
The output stays invisible until exit — a 15-minute connectivity test looked hung. Stream to a log file and follow it instead.
jul 14 · phase 3bitten
Read the error output of destructive commands — especially when they "worked".
kubectl delete ds kube-proxy cm/kube-proxy errors (can't mix bare and resource/name forms) — the delete silently didn't happen while the iptables flush did. kube-proxy would have recreated its rules; caught only because the output was actually read.
jul 18 · phase 6.5bitten
One driver at a time.
A "stuck" run that's actually in a retry loop resumes the moment you fix the blocker. Starting a second bootstrap alongside it made both fight over apt locks on every node. Fix the blocker, let the original finish.
jul 18 · resurrectionbitten
Every quoting layer is a chance to mangle the query.
A LIKE pattern with escapes, passed through psql-inside-shell-inside-exec, broke three layers deep. The exact-match form (WHERE query = '...') survives; prefer it when counting things through nested shells.
jul 18 · 7.2bitten
Interactive CLI wizards need a real TTY.
aws configure sso can't run through a non-interactive shell — some tools must be driven from a real terminal, and it's worth knowing which before scripting around them.
jul 13observed

My stopwatch started when I armed it, then the user read an explanation before firing — so "109 seconds" measured their reading speed, not the failover. The cluster's own event record gave the honest numbers: 2s to detect, 23s to full recovery. Always ask what your measurement's zero point actually is.

kubectl dies with the apiserver, so the fence drill was observed via SSH + crictl exec on the node plus external curl for the control app. Designing the periscopes was half the drill — and the reason the result is trustworthy.

The pattern behind this whole section: almost nothing here is a Kubernetes lesson. It's session lifetime, quoting, pastes, and unread error output — the failure surface of driving remote systems from a terminal. The drills made these cheap to learn; production would have made them expensive.

The five drills — breaking it on purpose

The capstone card, run against a database holding this cluster's own inventory. Every measurement below came from a deliberate breakage.

Deleting the primary pod is a switchover, not a crash test.
The "dead" primary kept serving writes for three minutes after kubectl delete: CNPG uses the termination grace to run an orderly handover, and the delete command blocks while it does. Total write gap 31s, zero rows lost. Real crash semantics need --grace-period=0 or an actual lost node — otherwise you are measuring the polite path and calling it a failure.
aug 18 · drill 1observed
The pooler is what turns an outage into a slow moment.
124 requests entered a 31-second window with no writable database; 116 succeeded. PgBouncer holds clients rather than refusing them, then replays onto the new primary once the rw endpoint moves. The indirection added in 7.2 paid for itself in one drill.
aug 18 · drill 1observed
A resource request is a promise to the scheduler — and ours was a lie.
NetBox requested 512Mi and spiked past 1.5Gi at boot, so the scheduler packed two booting pods onto one 4Gi worker. The node didn't OOM-kill a container; it thrashed until its kubelet went silent and the taint manager evicted everything. Three node-wedges in an afternoon, all the same arithmetic in different disguises — a dishonest request, then an RWO volume pinning every replica to one node, then platform pods with no requests at all hiding the real free memory.
aug 18 · drill 2bitten
Chart-generated secrets under GitOps are time bombs with a per-sync fuse.
Helm's lookup returns empty under helm template — which is how Argo CD renders — so an upgrade minted a fresh Valkey password mid-rollout. Valkey restarted with it and every running pod died on stale cache credentials: nine minutes of 500s, from a secret we had never pinned. Every other NetBox secret had been pinned for exactly this reason; the subchart's was missed.
aug 19 · drill 2bitten
Hard anti-affinity plus surge rollouts deadlock when replicas equal nodes.
RollingUpdate wants room for an extra pod; required anti-affinity says that room cannot exist. The surge pod stayed Pending forever while the old, already-broken pods squatted both workers — the deployment could neither advance nor retreat. Fix: maxSurge: 0, roll down first, accept a brief single-pod window in exchange for a rollout that always completes.
aug 19 · drill 2bitten
The migration was innocent; the delivery machinery was guilty.
Schema migrations under multiple replicas — the thing the drill was designed to fear — applied exactly once with no observable lock contention. The nine-minute outage came entirely from the two config bugs above. Upgrades fail at the edges, not the centre.
aug 19 · drill 2observed
"It's just a cache" is a claim to verify, not assume.
Killing Valkey returned hard 500s for 22 seconds — sessions and config caching are load-bearing in NetBox, not a graceful-degradation layer. Meanwhile the thing predicted to die, the RQ job queue, survived intact: bitnami ships appendonly-yes onto a PVC and a StatefulSet pod returns as itself, so the AOF replayed. Both textbook predictions inverted in one drill.
aug 19 · drill 3observed
Infrastructure death is cheaper than configuration betrayal.
Valkey pod killed: 22 seconds, self-healing, zero hands. Valkey password rotated: nine minutes, every pod, manual intervention twice. The pod is cattle; the credential is a contract.
aug 19 · drills 2–3observed
A restore that doesn't resume backups isn't finished — and neither is one you live on.
PITR rebuilt the database 4 seconds before a cascading delete in 35 seconds: the deleted machine existed again, a table written after the target did not. But recovery only ended when the app was repointed back to the canonical cluster, its hole healed by re-running the idempotent populate script, and the restored cluster was archiving under its own generation name.
aug 26 · drill 4observed
The platform survives in git; the data survives only in object storage.
Every earlier rebuild "kept" its data because populate.sh rediscovers infrastructure records from the live cluster — worthless for anything a human typed. Drill 5's cluster was born from the previous generation's archive: 8.5 minutes destroy-to-converged, one manual step, and populate found nothing to create but the three new public IPs. A quieter proof came free — no API token had to be minted, because the token file on the laptop still matched the row restored from blob.
aug 27 · drill 5observed
The instrument fails more often than the system under test.
Drill 5 took three attempts and every failure was in the harness: it measured an idempotent no-op and reported confident numbers; it died under set -e before printing its own scorecard; then it blocked on stdin that backgrounding had removed. The cluster passed every stage on the one attempt that ran. The same shape recurred all week — the drills kept finding our tooling rather than Kubernetes.
