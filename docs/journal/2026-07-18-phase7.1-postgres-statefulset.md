# 2026-07-18 — Phase 7.1: a single Postgres, by hand

First step of the Postgres progression: one instance, hand-written
StatefulSet + PVC, no operator — to see the guarantees before anything
automates them away. Deployed GitOps-style like hello (apps/postgres +
ArgoCD Application), credentials from a local file via platform.sh (the
Cloudflare-token pattern; `~/.config/trk-k8s/postgres-password`).

## What postgres:18 changed

The official image reorganized its volume layout: mount
`/var/lib/postgresql` (not `.../data`); PGDATA lives in a version dir
underneath (`/var/lib/postgresql/18/docker`). Point: a future major
upgrade can run `pg_upgrade --link` inside one volume. Worth knowing
before 7.x touches upgrades.

## The drill — three guarantees, each observed

1. **Stable identity.** Deleted postgres-0; the replacement was already
   named postgres-0 seconds later. No random suffix — the ordinal IS the
   identity. (A Deployment would have minted a new name and a new empty
   volume claim... if it could claim volumes at all.)
2. **Storage follows the pod.** `volumeClaimTemplates` minted
   `data-postgres-0`; the `survival` table row written before deletion
   was there after. The PVC binds to the ordinal, not the pod instance.
3. **Stable per-pod DNS.** `postgres-0.postgres.postgres.svc` resolves
   via the headless governing Service — per-pod names, not a VIP.
   Databases care WHICH instance answers; this is the primitive 7.3's
   primary/replica split builds on.

## The local-path trade, made visible

postgres-0 landed on worker-2, so local-path minted a hostPath PV with
nodeAffinity=worker-2. Cordoned worker-2 and deleted the pod → Pending,
with the scheduler saying the quiet part out loud:

> 0/3 nodes are available: 1 node(s) didn't match PersistentVolume's
> node affinity, 1 node(s) had untolerated taint(s), 1 node(s) were
> unschedulable.

Worker-1 was free; the data wasn't there. Uncordon → back on worker-2.
**Local storage pins the workload to the data's node.** ebs-sc (the
opt-in class from Phase 4) would have followed the pod instead — that
contrast is the whole local-vs-network storage decision in one drill.

## Carry-forwards

- **`pulumi destroy` kills Postgres data**: local-path = hostPath on the
  node's disk. Fine now (throwaway rows); real backup story (pg_dump /
  WAL archiving) is part of this phase — etcd snapshots don't cover PV
  data (drill 3 lesson stands).
- IP drift bit again MID-SESSION (ISP rotated twice today) — `make
  check-ip` caught it on its first real use. The guard already paid off.

  pooler in front.
