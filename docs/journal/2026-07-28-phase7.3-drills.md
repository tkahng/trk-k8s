# 2026-07-28 — Phase 7.3 (part 2): the failover drills

The payoff session. Five drills against the two-member Patroni cluster,
each proven with marker rows written through pgbouncer (the drill-3
technique, ported from configmaps to SQL). Every drill produced a lesson
the previous one hadn't; the last produced the best one of the phase.

First: this resume was the first **fully hands-off rebuild** — Step 4.5
gated the apiserver, the helm_i retry harness stood unneeded, and Patroni
bootstrapped trap-free in 35 seconds from pod creation to streaming
replica. Yesterday's four fixes all held. (`make destroy` → running HA
postgres is now two commands and zero interventions.)

## Lessons, in the order they were earned

- **`patronictl` doesn't read the daemon's config.** It assembled a
  partial config from `PATRONI_*` env vars and crashed on the missing
  `kubernetes.labels` (`KeyError`). Every invocation needs
  `-c /etc/patroni/patroni.yml`. The daemon gets file+env because PID 1
  is *launched* with the file; patronictl is just another process.
- **Layered recovery (2a).** Killing a pod on a healthy node is a
  process restart, and the layer built for that (the StatefulSet
  controller, seconds) outraces the layer built for real failures
  (Patroni's TTL, 30s). Failover correctly *didn't* happen. To drill the
  DCS layer you must disable the k8s layer first — hence the cordon.
- **A planned switchover and a hard failover differ by one word:
  checkpoint.** Switchover demotes first and loses nothing by
  construction. Hard failover's loss window is async replication lag —
  which our markers survived because they were long-replicated; a real
  loss demo needs a write-load generator (stretch item).
- **Rejoin ≠ rewind. Rewind is for divergence, and divergence has the
  same precondition as data loss** — commits the old leader had that the
  new one didn't. Our kill left none, so the ex-leader's recovery was a
  timeline fast-forward (`End of WAL reached on timeline 3` → `new
  target timeline is 4`), no rewind invoked. Two sides of one coin,
  observed on both faces.
- **Timelines are the forensic log of promotions.** TL went 1→5 across
  the day (switchover, 2a's silent resume, 2b, fence re-election). The
  "non-event" of 2a left a timeline bump as its only trace.
- **The fence works (drill 3, the ADR 006 trade made visible).**
  Manifest out → within TTL a *healthy* Postgres on a *healthy* node
  demoted itself (`in_recovery: f→t` at 08:24:05), because a leader that
  cannot renew its lease must assume a rival. The replica was equally
  fenced — no promotion, no split-brain, total write outage. Meanwhile
  `hello=200` never blinked: drill 3's "control plane down ≠ outage"
  held for everything except the thing whose consensus we moved INTO
  the control plane. Exactly the exception we signed for.
- **Writes fail *clean* under the fence.** Not timeouts — pgbouncer's
  server connections died with the demote, it redialed through
  Endpoints frozen by the dead apiserver, reached the standby, and
  clients got `cannot execute INSERT in a read-only transaction`.
  Read traffic kept working throughout.
- **No incumbency in a CAS race:** when the apiserver returned, the
  ex-REPLICA won the lease and promoted (TL 5). Leadership history
  carries zero weight; only the atomic write matters.
- **THE POOLER GAP (find of the day):** the database finished failing
  over at ~08:26:2x; writes stayed broken until 08:27:28+ because
  pgbouncer's pooled connections remained pinned to the demoted
  ex-primary — established TCP doesn't follow Endpoints, and
  `server_lifetime` defaults to an hour. `RECONNECT` on the admin
  console fixes it — but firing it through the Service VIP is a
  lottery (visible as OK/ERROR *flapping*: one pod flushed, one
  pinned). It took per-POD-IP RECONNECTs to flush both. Rules:
  **failover isn't complete until the pooler lets go**, and **fleet
  operations through a VIP aren't fleet operations** (7.2's "no fleet
  view" lesson, weaponized). Production automates this with Patroni
  promote/demote callbacks — noted as a follow-up, and as the best
  argument yet for what 7.4's operators do.
- **Probes must not depend on the layer being killed.** kubectl dies
  with the apiserver, so the drill was observed via SSH + `crictl exec`
  into the primary's container (role probe + write probe) and external
  curl through the gateway. Designing the periscopes was half the drill.

## Follow-ups

  to kick pgbouncer on role change — the pooler gap, automated away.

  demonstrate real async data loss during a hard kill.

  local-path PV death + replica re-init from the new primary.
