# 2026-07-15 — Phase 6, Drill 1: teardown → rebuild

Ran `make rebuild` against the live Phase-5 cluster. Results:

## Timing

| Stage | Time |
|---|---|
| `pulumi destroy` (14 resources) | ~2m45s |
| `pulumi up` (14 resources) | 39s |
| `bootstrap.sh` (prep ×3 parallel, init, joins, Cilium, Ready ×3) | ~2m |
| `platform.sh` (storage, ingress, metrics, cert-manager, argocd) | ~2m |
| **Machine-off to platform-restored** | **~8 min** |
| Let's Encrypt cert re-issued (new cluster, DNS-01) | +77s |

The 45-minute manual bootstrap is now an 8-minute command.

## The drill caught a real bug (that's what drills are for)

First run failed at Step 1: `scp: Connection closed` ×3 — bootstrap.sh
SSH'd into instances that Pulumi had *just* created; sshd wasn't up yet.
`pulumi up` returning ≠ machines ready. Fix: a Step 0 wait-for-SSH loop
(parallel, 150s timeout per node). Resume was painless BECAUSE the
scripts are idempotent — re-running `make bootstrap` skipped nothing it
needed and redid nothing it shouldn't.

## What restored itself (the GitOps dividend)

- ArgoCD came up, read its repo credential (platform.sh), found the
  `hello` Application, pulled main, deployed: Synced/Healthy with zero
  human involvement.
- cert-manager found the issuers + Cloudflare token (from the local
  token file), re-issued hello-tls in 77s. DNS-01 needs no inbound, so
  issuance worked even while the A record still pointed at the dead IP.
- The only human steps: update the Cloudflare wildcard A record to the
  new control-plane IP (DNS lives outside the cluster) and note the new
  ArgoCD admin password.

## Observations

- Everything of value lived in three places: git (manifests/scripts),
  Pulumi state (infra), local secret files (2 tokens/keys). The cluster
  itself held nothing worth keeping — which is exactly the design goal.
  Phase 7's Postgres will change that (real state!), which is why etcd
  backup and volume snapshots are the next drills.
- New-account PendingVerification did not recur (account now validated).
- Remaining drills: kubeadm upgrade (1.35→1.36), etcd backup/restore,
  node replacement.
