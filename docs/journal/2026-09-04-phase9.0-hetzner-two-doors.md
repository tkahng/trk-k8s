# 2026-09-04 → 09-09 — Phase 9.0 on Hetzner: two builds, two doors, one finish line

Six days, two clusters, a provider that had never run, and the sentence
9.0 was built to earn:

    Initialized=True          Cluster has been bootstrapped
    Ready=True                Cluster is Ready
    ContinuousArchiving=True  Continuous archiving is working

    s3://trk-k8s-pg-backups/pg-hetzner-20260909/wals/0000000100000000/000000010000000000000001.gz

A Postgres in Nuremberg, born 85 seconds after `kubectl apply`, shipping
WAL to a bucket in Virginia through a credential that never touched a
terminal. Phase 9.0 — "the platform from memory" — is complete on its
third attempt (Azure 09-01→03, Hetzner 09-04, Hetzner 09-08→09).

## Build one (09-04): the never-run program runs

`infra/hetzner/` had existed since July without ever provisioning a
machine (ADR 002: no capacity). Wired on 09-03 — Makefile's fourth header
swap, a `dev` stack on the S3 backend, per-role sizing (cx23 control
plane, cx33 workers — drill 2's verdict, ported), a NodePort firewall
rule — it previewed clean at 12 resources and `make up` bought three
servers in Falkenstein on the first try. The contract was honest: `make
nodes` returned `sshUser: root`, and the Makefile turned out to have
been **hardcoding `ubuntu@`** since day one — a contract violation only
the fourth swap could expose. Fixed.

Then `kubeadm init` hung at `wait-control-plane`, unable to reach
`10.0.1.10:6443` — **because 10.0.1.10 was not on the machine.** `ip -4
addr` showed `eth0` with the public address and nothing else. The private
NIC (`enp7s0`) existed, DOWN, unconfigured: Pulumi had created the server
and attached the network afterwards, and cloud-init had already written
netplan for the interfaces it saw at first boot. Live fix: a netplan
`dhcp4` rule for `enp7s0` on all three nodes; Hetzner's DHCP handed out
the fixed IPs and the route to `10.0.0.0/16`.

Second surprise, before Cilium: all three nodes had registered their
**public** address as `InternalIP`. Kubelet picks the default-route
interface, and on Hetzner that is the public one. Cilium would have
tunnelled pod traffic over public IPs — straight into the admin-only
firewall. Fix: `--node-ip=10.0.1.x` in `/etc/default/kubelet`. Third,
found by looking before installing: `enp7s0` has **MTU 1450**, `eth0`
1500. Cilium measures the default-route device; pods would have been
handed 1450 and had their packets silently dropped on the 1450 link.
Fix: `--set MTU=1400`.

These three are one finding, written up the same night as
`docs/notes/provider-network-models.md` — **one door vs two doors**. AWS
and Azure put a single NIC on the VM with the private address and NAT the
public one at the edge, so every "pick the default interface" decision
has one answer. Hetzner gives you two real doors, and every component
that guesses picks the wrong one. The inventory contract's `privateIp`
was *true* on Hetzner but not *usable* without telling the OS which door
is for family. Revised portability claim: the seam absorbs a cloud swap
completely as long as the cloud presents one door.

Cluster up, nodes Ready. Then (09-06) the servers were gone and Hetzner
had **no cx23 or cx33 to sell anywhere in the EU** — the July blocker,
again. Two responses, both repo work rather than waiting:

- **`make up PROVIDER=aws`.** The provider became a Makefile *variable*:
  both stacks on one S3 backend, both programs taking the same
  comma-separated admin-IP list (the Talos-era append-not-replace lesson,
  ported to both). AWS previewed clean at 15 resources against the
  persistent stack from the last era. Server types stay fixed at
  cx23/cx33 by decision — CPX costs 4×, CAX is arm64, neither is a
  variable this phase wants — so `make up` on Hetzner now preflights
  stock (`make capacity`) and fails fast with the AWS pointer.
- **Two admin IPs.** The user works from two places; `myIp` is a list,
  `check-ip` appends, `add-ip` admits a location ahead of time.

## Build two (09-08→09): Nuremberg, and the race

Stock returned on 09-08 — cx23 in Falkenstein, but cx33 only in
Nuremberg and Helsinki. Location moved to `nbg1`. And the program got
what looked like the durable NIC fix: the network attached *at server
creation* (`ServerArgs.Networks`) instead of as a separate resource.

`make up`, 9 resources, and the first check on cp-1: `enp7s0 UP
10.0.1.10` at first boot, no patch. Closed — or so it read. Then
worker-1's `kubeadm join` timed out on `10.0.1.10:6443`, and worker-1
had the September 4 symptom exactly: NIC present, DOWN, no netplan. cp-1
and worker-2 had won; worker-1 had lost. **Two of three is the
signature of a race.** Hetzner attaches asynchronously either way;
"attach at creation" only improved the odds. Live patch on the workers,
and the actually-durable fix committed the same hour: cloud-init
`user_data` writing a netplan rule that DHCPs *any* `enp*` interface —
systemd-networkd applies match rules to hot-plugged NICs too, so timing
stops mattering. It replaces servers, so it is **pending until a chosen
rebuild**, unverified. Runbook 09 says so in its status table.

The other two doors closed on the first try this time: `--node-ip` set
during prep, before join, and all three nodes registered private
addresses; Cilium installed with `MTU=1400` (after a first attempt left a
`failed` Helm release behind — uninstall, reinstall). Then storage, the
genuinely new layer: the `hcloud` API token as a Secret (**the first
cloud credential to live inside a cluster in this project** — Hetzner
has no instance identity), `hcloud-csi` with its bundled StorageClass
disabled, and a StorageClass rewritten with exactly one semantic change
(`provisioner: csi.hetzner.cloud`, no SKU block). Then the proof:
`pv-claim.yaml` and `pv-pod.yaml` from the Azure session, **byte for
byte** — `Bound`, `Running`, and `hcloud volume list` showing a 10 GB
volume on worker-1. Ten, not three: Hetzner's minimum, rounded up. Same
manifest, different cloud, different answer. The seam, seen.

09-09, the last leg. cert-manager first (the barman plugin's mTLS
certificates are cert-manager objects — `kubectl get certificate` showed
the two it minted). CNPG operator by Helm, barman-cloud v0.14.0. The
credential problem inverted from AWS: no instance role to ride, so the
persistent stack grew an IAM user scoped to the bucket policy, and `make
pg-backup-secret` moves its key from Pulumi state into a Kubernetes
Secret without printing it. ObjectStore in S3 form, and a Cluster
manifest written by hand: two YAML structure errors (a list written as a
mapping, a stray comma inside a value), zero content errors. Healthy in
85 seconds. `ContinuousArchiving=True`. Three WAL segments in S3 by the
time we looked.

## Recall, this time

Compared with the Azure attempt (journal 09-01), the same layers still
needed hints — but the *shape* of the asking changed. On Azure the
questions were "what is a kernel toggle" and "install docker?". On
Hetzner they were "which line does `--node-ip` go on", "how should my
pv-claim change" (answer: it shouldn't — and the user's instinct to ask
shows the seam wasn't yet felt), and "is MTU=1400 Hetzner-only". The
kubeconfig step tripped on a **stale IP copied from the previous
build's commands** — the flip side of new public IPs every rebuild, and
the reason `make kubeconfig` reads the inventory. The StorageClass and
Cluster manifests were written correctly in substance on the first
attempt. The prep block was reused, not recalled — which is fine; that
is what worksheets are for, and what `prep-node.sh` is for.

The honest verdict: the *procedure* is still guided; the *understanding*
of what each layer is for, and why each Hetzner difference matters, held
up under a cloud the user had never touched.

## Decisions made along the way

- **The stock rule** (09-09, user's rule): never replace or destroy
  Hetzner servers without confirmed stock. Enforced — `make up` runs
  `guard`, which refuses any server replace/delete in the preview; `make
  destroy` runs `capacity` first; `FORCE=1` overrides both. `make admit`
  exists so an IP change pushes only the firewall.
- **barman stays.** CNPG-I now has pgBackRest plugins (Dalibo v0.0.3,
  Opera); parked as a side-by-side lab, not adopted mid-9.0 — the known
  tool, so failures point at the new cloud.
- **The NetBox lineage ended with Azure**, by choice. Phase 9's data
  starts from zero, archiving to S3 from its first WAL segment.

## Findings the answer key didn't know

1. Hetzner private NIC attachment is asynchronous; only a standing
   netplan match rule (cloud-init) survives the race. Pending.
2. kubelet `--node-ip` is mandatory on any two-door provider, before
   the node registers.
3. Hetzner private-network MTU is 1450; Cilium needs `MTU=1400`.
4. The Makefile hardcoded `ubuntu@` — the contract had `sshUser` for
   exactly this and nothing read it.
5. The barman-cloud plugin depends on cert-manager (mTLS certificates).
6. Off-AWS clusters need a static IAM principal for barman; the
   persistent stack is where it belongs.
7. Hetzner volumes are 10 GB minimum; `hcloud-csi` ships a default
   StorageClass that must be disabled if you bring your own.
