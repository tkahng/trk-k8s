Why the sizes are uneven — quota, not preference. Standard_B2als_v2 was the perfect match (burstable, 2 vCPU/4 GiB, $0.0376/hr — identical to t3a.medium in shape and price) but the entire B-series is capacity-restricted on a trial subscription. az vm list-sizes reports it available; only az vm list-skus's restrictions field tells the truth — 16 of 522 visible SKUs are actually usable. Then Total Regional vCPUs is capped at 4 (identical in eastus, westus2, centralus, eastus2 — relocating doesn't help), so three 2-core nodes were impossible. The fix keeps the full topology inside 4 cores: a 2-core control plane (kubeadm's NumCPU preflight requires 2) plus two 1-core workers, every node still 4 GiB. Phase 1's lesson, third and fourth occurrence: a provider listing a product is not the same as having capacity for you.

Three clouds, three different answers to the same question. Hetzner firewalls filtered only the public interface, so private traffic was unfiltered. AWS security groups denied everything including node-to-node, which forced an explicit self-referencing rule. Azure allows all intra-VNet traffic by default, so that rule has no counterpart at all. This is precisely the class of difference ADR 002 said the inventory seam existed to absorb — and the reason cluster/ never had to know.

The firewall was never opened to the world. Real TLS still works because cert-manager proves ownership with DNS-01 records on Cloudflare — Let's Encrypt never reaches the cluster. On migration day the wildcard cert issued in ~2.5 minutes, before the DNS A record was even repointed.

The 7.4 backup lab archived to s3://trk-k8s-pg-backups with inheritFromIAMRole, and measured a restore into a cluster that never existed at exactly one row lost of 660 — the RPO is the currently-open WAL segment. The bucket and the account are both gone, so the config was removed rather than left failing. CNPG supports azureCredentials with inheritFromAzureAD, and id-trk-k8s-node exists for exactly this; the port needs a blob container and a Storage Blob Data Contributor assignment. Its own lab, as it was on AWS.

Two warnings that survive the migration. pg_stat_archiver.archived_count climbed to 15 and the cluster reported “Continuous archiving is working” while the bucket sat empty — CNPG's archive command exits 0 with no destination configured, so the only honest check is listing the bucket. And the whole reason the bucket now lives in a locked resource group is that the first version died with a destroy.

The fence result overturned our own ADR. ADR 006 recorded that using the Kubernetes API as the DCS bought “control-plane outage = database write outage.” CNPG runs on the same API and kept serving — while logging 128 Failed to watch errors, so it knew and chose. The coupling belongs to Patroni's self-promoting leader model, not the API: a leader whose claim is a renewable lease must demote when it can't renew, because any peer might have taken over. CNPG centralizes promotion in the operator, so when the API is unreachable nobody can promote — and the incumbent is safe to continue. Corrected in ADR 007.

phases

Phase 0–1 · Tooling, accounts, machines done jul 13

Pulumi Go programs for Hetzner, then the pivot: no CX23 capacity, so AWS (3× t3a.medium, ~$0.35 per 3-hour lab on credits). The pivot forced the project’s best idea — the provider-agnostic inventory contract.

Phase 2 · kubeadm bootstrap, by hand done jul 14

certs, static pods, etcd, join tokens — cluster up at v1.35.6, deliberately NotReady awaiting a CNI.

Phase 3 · Cilium done jul 14

Cilium 1.19.4 via Helm; nodes Ready, connectivity test 79/80, Hubble running.

Phase 4 · Storage done jul 14

local-path as portable default; EBS CSI opt-in. The IMDS hop-limit-3 bug, debugged with Hubble, was the phase’s best lesson.

Phase 5 · Platform done jul 14

metrics-server, ingress-nginx, cert-manager with DNS-01 on Cloudflare (real certs, closed firewall), hello app, ArgoCD syncing from the private repo.

Phase 6 · Automate & drill done jul 15

  • Drill 1 — teardown → rebuild in ~8 min · caught the SSH-readiness race
  • Drill 2 — rolling upgrade v1.35.6 → v1.36.2, zero downtime
  • Drill 3 — etcd snapshot → destroyed data dir → restore · proven by time-travel markers
  • Drill 4 — unannounced node kill → replacement Ready in ~7 min

Phase 6.5 · Gateway API migration done jul 18

ingress-nginx retired upstream (mar 2026) → Cilium Gateway API (ADR 005): kube-proxy replaced with eBPF, Gateway API v1.4.1, hostNetwork Envoy on the same ports, TLS moved from app manifests to infra. URLs and firewall unchanged through the cutover.

Phase 7 · PostgreSQL 7.5 remaining jul 18 → aug 1

The named end-goal: state you care about, on a cluster you can rebuild. Built by hand first, on purpose — which is the only reason the operator's numbers mean anything.

  • 7.1 ✅ StatefulSet + PVC — identity and data survive pod deletion; local-path pins the pod to its data
  • 7.2 ✅ PgBouncer — pooling (5 clients / pool of 2), Deployment-vs-StatefulSet, VIP-vs-headless
  • 7.3 ✅ Patroni HA on the k8s-API DCS · four bootstrap traps (scope-name collision, OrderedReady deadlock, the invisible scope label, a trailing newline splitting env-auth from pgpass-auth); five drills — including the self-fence, and the pooler gap that cost 3 minutes
  • 7.4 ✅ CloudNativePG · ADR 007. Pooler gap closed (3min → 2s), detection 30s → 2s, cordon = graceful evacuation, and no fence on a 7-min apiserver outage — which disproved ADR 006. Plus backups: S3 WAL archiving, restore in 52s, RPO measured. Zalando dropped — comparison already made.
  • 7.5 — Capstone · Saleor or Supabase end-to-end behind the gateway, on CNPG

Cloud migration · AWS → Azure done aug 5

Not a planned phase — AWS account access was lost, taking the Pulumi state backend and every Postgres backup with it. The forced rebuild became the experiment ADR 002 had been promising since day one.

  • The seam held. Changed: the Makefile header and a new infra/azure/. Unchanged: prep-node, bootstrap, every Cilium and gateway value, all of apps/ and gitops/. make bootstrap brought up v1.36.3 on Azure first try.
  • Earned by three earlier calls · sshUser carried as data; the address plan pinned identically; and ADR 003's refusal to install a cloud-controller-manager — the thing deliberately NOT built is what made the swap free
  • One honest seam · platform.sh's WITH_AWS boolean became --provider=aws|azure|none; Azure Disk CSI joins EBS CSI as an opt-in class
  • Quota, not preference · B-series capacity-blocked, 4-vCPU regional cap → per-role sizing (2-core cp + two 1-core workers)
  • Foundation is a SCRIPT now · the AWS state bucket was hand-made and documented only in prose; that knowledge died with the account

Phase 8 · Talos comparison lab planned

Rebuild on Talos Linux and judge it against kubeadm+Ubuntu (ADR 004). Deliberately after Phase 7: the interesting drill is rebuild-with-state, with real Postgres data at stake. Not a provider swap — no SSH means the whole cluster/ layer becomes machine configs + talosctl; infra/ survives unchanged.
